## Purpose

This spec defines requirements for distinct image mode, a dedicated view accessible via the sidebar "Image" link that allows users to generate images from text prompts with configurable generation options. It reuses existing backend infrastructure (ComfyUI pipeline, `PromptGenerator`, event system) and follows the same UX patterns as composite mode.

## Requirements

### Requirement: User provides a text prompt to generate an image

The user SHALL be able to enter a custom text description into the distinct mode view, which will be used as the generation prompt sent to ComfyUI.

#### Scenario: Empty prompt is rejected
- **WHEN** user clicks "Generate" without entering any text in the prompt field
- **THEN** system displays an error message and does not submit a job

#### Scenario: Prompt submitted generates image
- **WHEN** user enters a prompt and clicks "Generate"
- **THEN** system posts the prompt to `/api/jobs/images` and creates a new job with `JobMode.Image`

### Requirement: Distinct mode view is accessible from sidebar

The distinct mode interface SHALL be reachable by clicking the "Image" item in the application sidebar.

#### Scenario: Sidebar navigation loads distinct mode
- **WHEN** user clicks the "Image" sidebar link (`/create/image`)
- **THEN** system renders the distinct mode form with an empty prompt field and placeholder image

### Requirement: Generation parameters are configurable

Users SHALL be able to configure generation options before submitting.

#### Scenario: Batch size controls number of images
- **WHEN** user sets batch size to N (where N > 1)
- **THEN** system generates N images for the prompt, all belonging to the same job

#### Scenario: Resolution is applied to generated image
- **WHEN** user selects a resolution option ("480p" or "720p") matching composite mode's available presets
- **THEN** system passes the corresponding dimension (640x480 for 480p, 1280x720 for 720p) to ComfyUI and the output image matches the selected size

#### Scenario: Style preset modifies image appearance
- **WHEN** user selects a style preset from available options
- **THEN** system applies the corresponding style instructions to ComfyUI, modifying the visual output accordingly

### Requirement: Image prompt(s) are generated from user input

When a job is submitted with generation parameters (prompt, batch size, resolution, style), the backend SHALL use `PromptGenerator.txt_to_img_prompt()` to create one or more image prompts for ComfyUI.

#### Scenario: Single prompt generates single image
- **WHEN** user submits a prompt with batch_size=1 and a specified resolution and style preset
- **THEN** system calls `PromptGenerator.txt_to_img_prompt(jobId, JobMode.Image, prompt, 1, presets[preset])` which returns one image prompt to dispatch

#### Scenario: Batch generates multiple prompts
- **WHEN** user submits with batch_size > 1
- **THEN** system generates N distinct image prompts (one per generated image) and queues each for ComfyUI processing

### Requirement: Generated images are dispatched to ComfyUI via events

After generating the image prompt(s), the backend SHALL dispatch them through the event system (`Event.NewImagePrompt`) so that `ImageGenerator` receives them from the queue.

#### Scenario: Image prompts queued for generation
- **WHEN** `text_to_image()` has generated its prompt(s) and created the job record
- **THEN** each image prompt is dispatched as an event that triggers `QueueManager.imageQueue.push(event)` in `ImageGenerator`

### Requirement: Job data and events are persisted to the database

The backend SHALL persist the job metadata (prompt, resolution, style preset, batch size) and all processing events (queued, started, completed, failed) to the SQLite database.

#### Scenario: Job record created on submission
- **WHEN** user submits a generation request and `JobOrchestrator.create_job()` is called
- **THEN** a job row is written with mode=Image, resolution, style_preset, and status=pending/queued

#### Scenario: Events logged during processing
- **WHEN** images are generated by ComfyUI (via Event.ComfyExecuted)
- **THEN** each event is persisted so the user can track progress via `/jobs?job_id={id}`

### Requirement: Generated images are displayed after completion

The backend SHALL complete `text_to_image()` and fire Event.ComfyExecuted on the event stream. HTMX on the page listens via SSE and swaps in a response containing the generated image(s).

#### Scenario: Full flow from submission to rendered result
- **WHEN** user submits prompt + options via HTMX form POST
- **THEN** `hx-redirect` sends user back to `/create/image?job_id={id}` which has an SSE element connected to the event stream; after ComfyUI completes, Event.ComfyExecuted is delivered and HTMX swaps in generated image(s)

#### Scenario: Only current job's images shown
- **WHEN** a user has previously completed images and generates new ones via distinct mode
- **THEN** the view displays only the newly generated images for the active job, not older gallery items

### Requirement: Job metadata is preserved and visible

Each generated image SHALL be associated with its prompt text so users can see what they asked for.

#### Scenario: Prompt shown alongside result
- **WHEN** an image job completes and the user views it
- **THEN** system displays both the generated image(s) and the original prompt that produced them
